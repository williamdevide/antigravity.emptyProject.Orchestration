# Prompt para Geração da Interface via Google Stitch

Use `documentation/directives/design/5.design.md` como especificação visual oficial e `documentation/directives/project/5.projeto.md` como contexto funcional.

## Pré-condições

Antes de gerar a interface:

1. Confirmar se Google Stitch está configurado.
2. Ler o contrato em `integration-contracts.md`.
3. Identificar Project ID e nome sem expor credenciais.
4. Confirmar modo de uso: `source-of-truth`, `reference` ou `disabled`.
5. Confirmar nível de fidelidade: `exact`, `close` ou `inspired`.
6. Se a integração estiver indisponível, declarar `blocked` ou `not-verified` e usar somente o fallback documentado.

## Regras de implementação

- Implementar primeiro mobile-first.
- Seguir tokens, telas, componentes, fluxos e estados de `5.design.md`.
- Usar `ui-patterns/` para padrões existentes.
- Não inventar telas, cores, componentes ou comportamentos contraditórios.
- Criar navegação funcional entre telas principais.
- Implementar loading, error, empty, success, disabled e offline quando aplicável.
- Garantir contraste, foco, labels, áreas de toque e reduced motion.
- Usar dados de demonstração realistas e claramente identificados.
- Diferenciar visualmente o que está conectado ao backend do que é demonstrativo.
- Não afirmar fidelidade sem executar comparação.

## Validação visual

Produzir relatório com:

- telas comparadas;
- assets comparados;
- tokens comparados;
- divergências de layout, espaçamento, cor, tipografia e comportamento;
- percentual ou classificação de fidelidade, somente se medido;
- limitações;
- correções pendentes;
- status `verified`, `partial`, `blocked` ou `not-verified`.

## Resultado esperado

Gerar um protótipo navegável e responsivo, consistente com `5.design.md`, e retornar também as evidências e limitações da integração. Não executar alterações destrutivas nem expor credenciais.
